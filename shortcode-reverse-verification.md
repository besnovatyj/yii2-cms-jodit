# Реализация и проверка обратного преобразования шорткодов

Дата: 2026-11-15.
Основание: [утверждённый план](shortcode-reverse-plan.md), включая замечание об исключении при повторной программной регистрации.

## Реализовано

### Модуль шорткодов

- Неизменяемое полное определение, типизированный `ReverseMode`, встроенный поставщик и единый реестр.
- Ленивые singleton менеджера, реестра и каталога. Компонент приложения и constructor injection используют один менеджер без рекурсивной привязки.
- Повторное программное имя, включая встроенное, выбрасывает исключение. Пакетная регистрация атомарна.
- БД полностью переопределяет код, включая reverse. Удаление записи возвращает программное определение.
- Общие эффективные значения для API, справочника и серверного резолвера; однопроходная прямая подстановка.
- Поле `reverse_mode`, новая миграция, настройка в форме и проверки эффективного набора перед сохранением/удалением.
- Раздельный кэш строк БД и программного слоя; инвалидация общего и локального кэша после CRUD.

### Jodit

- Загрузчик с проверкой JSON, объединением запросов и повтором после ошибки.
- Общий URL/HTML-преобразователь без конкретных имён шорткодов.
- Прямое превью и выборочный reverse в `src`, `href`, `poster`, `srcset`.
- Сохранение существующих токенов и корректная обработка устаревших меток после изменения адреса.
- Проверка домена/порта и границ пути, выбор самого длинного префикса, сохранение закодированного остатка URL.
- Обязательная готовность правил, явная панель ошибки с повтором, readonly и блокировка штатного submit соответствующей формы.
- Синхронизация source/textarea, включая немедленную отправку после последнего ввода без ожидания debounce source-плагина.
- Очистка подписок при уничтожении, сохранение исходного readonly, независимость редакторов разных форм.
- Пересобран production-бандл `dist/jodit-widget.js` и source map. CSS не изменился.

Файловый менеджер, темы, контентные модули и серверный путь сохранения HTML не изменялись. Автоопределение установки модуля и переезды между доменами остаются вне работы.

## Пройденные проверки

### PHP 8.4 и настоящий Yii2

В окружении не было нативного PHP. Для выполнения использован изолированный PHP 8.4 WebAssembly с PDO SQLite. Инструменты находятся в `/tmp`, конфигурация рабочего приложения не подключалась.

Команда для обычного PHP с необходимыми расширениями:

```sh
php tests/registry.php
```

Проверены:

- оба порядка первого обращения к менеджеру: component-first и DI-first;
- видимость runtime-регистрации в реестре;
- исключения для дубликатов, включая встроенный шорткод;
- атомарность пакетной регистрации;
- валидация вложенных токенов, недопустимых префиксов и одинаковых префиксов с разным регистром/стандартным портом;
- сохранение виджетной регистрации;
- create/edit/remove, полный приоритет БД, выключение reverse и возврат встроенного определения;
- согласованность read model с серверным резолвером;
- инвалидация кэша через настоящий `ArrayCache` Yii2 и снимка текущего запроса;
- миграция up/down на изолированной SQLite с сохранением исходной таблицы.

В тестовом SQLite schema адаптирован только SQL builder для поддерживаемого движком `DROP COLUMN`, который стандартный SQLite builder установленного Yii2 запрещает. Рабочая миграция не содержит SQLite-обходов ради теста.

Дополнительно выполнен синтаксический разбор PHP-исходников модуля через `token_get_all(..., TOKEN_PARSE)`.

### TypeScript и сборка

```sh
npm run type-check
npm run build
```

Проверка strict TypeScript и штатная сборка ESBuild завершились успешно.

### Настоящий Jodit 4.15.14 в Chromium

Браузерные тесты: `tests/shortcodes.mjs`. Playwright, Chromium, необходимые библиотеки и шрифты установлены/распакованы изолированно; зависимости проекта не изменялись. Тест собирает отдельный бандл из актуальных исходников и запускает локальный HTTP endpoint с управляемыми ответами.

Проверены:

- преобразование изображений, ссылок и poster;
- `srcset` с несколькими кандидатами и `data:`;
- кириллица в URL-кодировании, `%20`, query, fragment;
- похожий чужой домен, граница пути, вложенные префиксы, стандартный порт;
- сохранение ручного токена с выключенным reverse;
- неизменность текстовых узлов и идемпотентность;
- устаревшая метка после замены изображения;
- прямое раскрытие одним проходом;
- совпадение source и textarea, возврат в WYSIWYG;
- старт в source и split;
- немедленный submit после ввода в source;
- undo/redo после вставки изображения через тот же API Jodit, который использует проводник;
- один запрос для нескольких редакторов;
- HTTP-ошибка и некорректный режим API, явная блокировка и успешный повтор;
- блокировка общей формы до восстановления всех редакторов;
- независимость другой формы;
- уничтожение редактора во время загрузки и снятие его блокировки формы;
- исходный readonly и явно выключенная интеграция.

Ошибок JavaScript в этих сценариях не зарегистрировано.

## Границы проверки и поставка

- Рабочая MySQL и существующие данные не изменялись. Применение миграции на MySQL через modman остаётся шагом поставки.
- Тест использует настоящий Yii2, но изолированное приложение; конфигурация конкретной установленной CMS и её формы не запускались.
- В браузере проверяется API вставки Jodit; реальный файловый менеджер с рабочим хранилищем не запускался.
- Проверен встроенный source engine `area`; внешний Ace с загрузкой с CDN отдельно не проверялся.
- Поддержка текстовых шорткодов при выводе остаётся ответственностью темы.
- Серверной гарантии против намеренного обхода штатного submit нет; серверных преобразований контента не добавлено.
- Пользовательские цитаты в анализе сохранены. Проверка diff исходников выполнена отдельно от исходного анализа, где в пользовательских цитатах есть завершающие пробелы.
- Коммиты, теги и push не выполнялись.

Порядок поставки: применить новую миграцию модуля Shortcode, использовать обновлённый API, затем опубликовать пересобранные ассеты Jodit. После обновления определений перезагрузить страницу редактора.
